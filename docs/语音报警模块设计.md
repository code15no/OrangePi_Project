
# 基于香橙派的疲劳驾驶检测的语音报警模块设计

## 一、总体目标
本系统利用 YOLO 系列算法在香橙派（Orange Pi）上实现疲劳驾驶检测，并通过语音报警模块进行实时预警。该模块旨在：
1. 将视觉算法识别结果实时转化为语音提示；
2. 实现低延迟（报警延迟 < 1s）；
3. 避免重复报警与误报；
4. 支持离线语音合成（TTS）；
5. 可配置报警策略和日志记录。

## 二、系统架构
1. **YOLO检测器**：识别驾驶员面部、眼睛、嘴部等特征。
2. **关键点与姿态检测**：计算 EAR、MAR、Head Pose。
3. **决策引擎（Decision Engine）**：根据多特征融合得出疲劳程度评分。
4. **语音报警模块（TTS）**：根据告警等级触发语音提示。
5. **配置与日志**：支持参数配置与报警记录。

数据流：  
Camera → YOLO检测 → 关键点分析 → 疲劳判断 → TTS播报

## 三、算法与阈值设计
### 1. 特征指标
- **EAR（Eye Aspect Ratio）**：闭眼检测  
  EAR < 0.20 且持续 > 0.5s → 疲劳信号  
- **MAR（Mouth Aspect Ratio）**：打哈欠检测  
  MAR > 0.6 且持续 > 0.8s → 疲劳信号  
- **Head Pose**：头部下垂检测  
  Pitch 角过大持续出现 → 疲劳信号

### 2. 综合评分
score_t = w1 * P(yawn) + w2 * P(eye_close) + w3 * P(head_down)

当平均评分 > 0.5 → WARN1（轻度提醒）； >0.75 → WARN2（严重提醒）。

### 3. 状态机设计
NORMAL → WARN1 → WARN2 → ESCALATE  
- WARN1：轻度提醒  
- WARN2：语音提醒  
- ESCALATE：紧急提示并记录

设置滑动窗口（短期 1s，长期 60s）与重复抑制（60s 内不重复提示）。

## 四、语音报警模块设计
### 1. 离线TTS选择
推荐：
- eSpeak / eSpeak NG：轻量快速，适合离线使用；
- PicoTTS：声音更自然；
- 预录制WAV：对紧急提示实现零延迟播放。

### 2. 报警语句模板
| 等级 | 语音内容 | 重复间隔 |
|------|------------|-----------|
| WARN1 | “注意：检测到疲劳征兆，请注意休息。” | 60s |
| WARN2 | “您可能疲劳驾驶，请尽快在安全处休息或靠边停车。” | 60s |
| ESCALATE | “危险！请立即靠边停车休息。” | 90s |



## 五、嵌入式优化建议
1. **模型优化**：使用 YOLOv5s / YOLOv8n / Nano 模型；量化为 FP16 或 INT8。  
2. **分辨率调节**：输入尺寸降低至 320x320 提升帧率。  
3. **推理框架**：ONNX Runtime / NCNN / Tengine。  
4. **关键点检测**：仅在人脸检测到时执行 ROI 推理。  
5. **资源管理**：TTS 与检测分线程运行，缓存常用语音。

## 六、伪代码实现（Python简化版）
```python
from queue import Queue
from threading import Thread
import subprocess, time

play_queue = Queue()

def tts_player():
    while True:
        text = play_queue.get()
        if text.endswith(".wav"):
            subprocess.run(["aplay", text])
        else:
            subprocess.run(["espeak", text])
        play_queue.task_done()

Thread(target=tts_player, daemon=True).start()

while True:
```

## 七、评估指标
- **Detection-to-Alarm Latency** < 1.0s；  
- **误报率**：< 1 次/小时；  
- **主观舒适度测试**：语音频率与音量调优。

## 八、常见问题与对策
| 问题 | 原因 | 解决方案 |
|------|------|-----------|
| 误报过多 | 光照、姿态异常 | 使用多模态融合（EAR+MAR+Pose） |
| 夜间识别差 | 红外光不足 | 加装红外摄像头或NIR模型 |
| TTS延迟 | 实时合成耗时 | 使用预录音或缓存机制 |
| 系统卡顿 | 模型过大 | 模型剪枝、量化、降低输入分辨率 |
